# Codex 开发任务：变量单位模型训练工作台

版本：unit-v1 / 2026-09-29
状态：开发交接规格，尚未提交到 Codex 执行；不代表工作台已经搭建或模型已训练完成。

## 1. 要交付什么

请直接实现一个可运行的本地全栈项目，而不只是写方案、画静态页面或模拟训练动画。

用户最终想做一个知识网络：每个变量单位独立存储、以后相互连接。本项目只交付该网络前面的**变量单位提取模型及其训练工作台**；知识网络存储、关系连边、实体合并、概念归一化和长期记忆均不在范围内。

### 用户明确要求

- 前端与后端分离。
- 使用本机 GPU，从零训练约 100M 参数的模型。
- 先预训练学习中文上下文，再后训练学习变量单位提取。
- 白色极简风格，中文界面，两张主页面，均为三栏布局。
- 首页是预训练：左侧为预训练内容输入框；中间为参数可视化观察、训练设置、新建训练模型、开始训练；右侧为聊天样式的测试框。

### 本交接包补全的工程方案（不是用户逐项指定）

第二页设计为后训练：左侧维护标注样本，中间选择预训练检查点并训练，右侧测试提取并纠错。技术栈建议 React + TypeScript + Vite、FastAPI + PyTorch、SQLite + 本地文件、独立训练进程。现有项目有合理等价技术时可沿用，但不得退回前后端混在一起的原型工具。

模型采用字符级双向编码器 + 掩码预训练输出层 + 二分类边界输出层。结构、公式及默认 100M 配置见 `MODEL_SPEC.md`。这是首版实验方案，不是对中文泛化效果的保证。

## 2. 任务语义：识别“变量单位”，不是抽关键词

两条用户确认的完整金标：

```json
{"text":"我养了一只猫叫魔丸","units":["我","养","了","一","只","猫","叫","魔丸"]}
{"text":"我养了十二只猫，它们都很乖很可爱","units":["我","养","了","十二","只","猫","，","它","们","都","很","乖","很","可爱"]}
```

必须遵守：正文成分不筛除，按原文顺序逐次输出；“了”保留；数字的位数不决定单位个数；“一”和“十二”各自是完整数值，与“只”分开；“魔丸”整体；“它 / 们”分开；“可爱”整体；逗号保留。出现两次的“很”输出两次，不提前去重。

输出只包含原文连续、不重叠的片段。所有单元完全覆盖输入。因此 `"".join(units) == text` 是数据与接口硬约束，不是准确率指标。单位边界对不对还需要金标判断。

禁止把旧例子里的“一只合并”“只保留有意义的词”“删除了”“先删除标点”当作本任务规则。旧附件 `verification_results.json` 的 `gold_units` 等字段包含已过时标签，不能沿用其旧训练准确率作为新任务验收。

### 尚未被用户完整定义的边界

负数、小数、日期、英文、网址、emoji、组合字符、更多词缀、连续标点等没有完整金标。实现原文无损处理与人工标注机制即可；不要声称某个自动切法已被用户确认。新人工规范需版本化。逗号保留不等于“小数点必定独立”。

首版统一采用 Unicode 码点位置。后端按 Python 字符串位置切片；前端不要用 UTF-16 的 `string.length/slice` 直接解释后端码点偏移，用后端返回的单位文本或 `Array.from(text)`。不自动做 NFC、繁简转换、空白裁剪。

## 3. 两页三栏界面

### 共同设计

白色背景、深灰文字、浅灰细边框、少量状态强调色；留白充足，不做暗色控制台或过度装饰。顶栏只有“预训练 / 后训练”主导航，以及本地连接、设备、当前任务状态。桌面建议左 30% / 中 42% / 右 28%，各栏可独立滚动；该比例为可调整设计值。窄屏可依次堆叠，但主桌面仍保持三栏。

所有按钮提供真实的禁用/运行/失败状态。设置有中文说明；新建模型和开始训练是不同动作。没有实际训练数据时不能画假曲线。

### 第 1 页：预训练 `/pretrain`（默认首页）

**左栏：预训练内容**

大文本输入框、字符数与长度预览、保存为数据集、导入 UTF-8 TXT/JSONL、选择已有数据集、训练/验证分组及统计。TXT 可作为一个完整文档记录；JSONL 每行是一个 JSON 记录，其中 text 内可含转义换行。文件编码 BOM 可去掉并记录，正文空白不可静默清除。较大语料走后端文件流和预处理索引，不能把全部语料长驻浏览器内存。

**中栏：模型、观察、设置、控制**

新建模型：名称、说明、默认 100M 配置、随机种子、词表构建与覆盖率；实际参数量由后端计算。新建只是配置或初始化，不自动进行正式训练。

可视化：模型结构与各层参数数量、train/val MLM loss、掩码位置准确率、真实 step/epoch、学习率、梯度范数、字符/秒、设备显存、耗时；可选展开查看抽样权重分布，不逐步传输整个参数矩阵。

训练设置：学习率、序列长度、微批次、梯度累积、训练步数或轮次、验证/保存间隔、遮盖比例、混合精度、梯度裁剪、激活重计算。基础设置直接可见，高级设置折叠。

控制：开始、暂停并保存、继续、停止并保存；检查点列表、best/last、下载导出、转到后训练。不允许重复点击创建两个占用同一 GPU 的训练任务。

**右栏：聊天样式的填空测试**

用户气泡输入正文，可选中某个字符“遮住”，再由模型气泡返回候选字符及概率。遮盖位置以结构化 `mask_positions` 传递，避免把 UI 的 `[MASK]` 当 6 个原文字符。

这是上下文填空，不是开放聊天、不做下一字续写、不用远程大模型作答。测试注明检查点 ID、step 和实际推理设备。没有检查点时显示提示，或明确标注随机初始化结果，不伪装成已训练。

### 第 2 页：后训练 `/finetune`

**左栏：标注工作区**

原文输入、单元标签编辑、逐间隙点选切开/合并、JSONL 导入导出。默认加载两条确认样例作为教学数据，不把它们称为充足训练集。显示 `units`、码点 span、gap labels 的实时一致性检查。

编辑只能改变分界，不能无提示改原文。相同 text、同一规范版本出现不同答案时标为冲突，阻止进入同一个训练版本。普通新增样本先在草稿；用户确认后进入标注集。不可调用现成分词库自动填金标并冒称用户规范。

**中栏：后训练与效果观察**

选择预训练检查点，创建新的后训练分支，保持原检查点不变。加载相同的编码器和词表，全参数微调边界分类器，默认不冻结主体。显示父检查点、规则版本、数据版本。

设置与控制复用预训练组件；观察 BCE loss、边界指标、片段级 precision/recall/F1、整句完全正确率、原文还原率，并区分训练集和验证集。没有独立验证集就显示“未评估”，不显示训练集成绩冒充泛化成绩。

**右栏：聊天样式的提取测试**

输入整句，输出单元标签流和 JSON，可展开每个间隙的分界概率与源位置；默认阈值 0.5，调整时在结果中记录。支持纠正边界并保存到“待审核标注”，不自动回流到训练集。

预训练检查点未经后训练时明确提示“边界头未训练”，不借助正则、词典或外部服务生成看似正确的答案。重复词不去重，逗号不删除。

## 4. 最小可运行技术结构

```text
frontend/               独立 React/TypeScript 页面、组件、API client、测试
backend/
  app/                  FastAPI 路由、schema、任务服务、SSE
  training/             model、tokenizer、collator、MLM、boundary、worker
  tests/                数据、训练、恢复、API 的自动化测试
scripts/                本地启动、环境检查、有限步数 smoke 命令
configs/                可版本化的模型和训练配置
workspace/              运行时数据/检查点/日志/SQLite，加入 .gitignore
README.md               中文启动和排错说明
```

开发服务器前后端分进程。FastAPI 只做 API 和调度，不在请求循环里长期训练。训练进程通过 spawn 或独立 subprocess 运行；Windows 不依赖 fork。SQLite 保存元数据，模型与大文件放本地磁盘；不引入 Redis/Celery/分布式集群作为首版依赖。

环境检查检测实际 OS、Python、PyTorch build、GPU、驱动兼容性、可用显存与精度支持。不能由本交接包推断用户显卡型号。优先实现单机单 NVIDIA CUDA GPU 路线；无兼容 GPU 时明确诊断，提供用户可选择的 CPU 小模型调试，但不能静默将 100M 正式训练降为 CPU、也不能声称完成本机 GPU 验收。

不要把训练 CUDA 驱动要求硬编码成一条适用于所有机器的安装命令。按实际硬件与官方安装说明选择、锁定并记录依赖版本。后端使用带类型校验的配置；不强制用户先装 Docker。

## 5. 数据、训练与检查点契约

数据结构以 `data/user_confirmed_units.jsonl` 为参考。后端校验原文、units、span、gap 长度与覆盖一致性。样本持久化包含 id、source/group_id、审核状态、rule_version、创建/修改时间；训练引用不可变的数据快照与哈希。

数据划分按文档来源/模板家族/同句改写分组，检测精确重复和明显近重复泄漏。先划分，再仅用训练集建立字符词表。测试集保持独立；验证集可调参数但测试集不参与选阈值或早停。仅两条教学样例不能伪造独立验证集；允许明确的 demo overfit 模式。

训练数据中的数字、名称、否定、数量、词缀和新句式需要用户标准标注；扩充数据是后续工作，不凭两条样例声称达到通用效果。生成式辅助标注若未来增加，必须人工审核，首版无外部调用。

保存检查点包括：模型权重、模型配置、词表及哈希、规范/数据版本、任务类型、父检查点、global step、optimizer/scheduler/scaler、Python/CPU/CUDA RNG 状态、数据读取顺序与游标。统一在完成一次 optimizer update 后保存；没有必要恢复半个梯度累积窗口。自动驾驶式“暂停”先进入 pausing，完成一致性保存后再报告 paused。

暂停、继续沿用原任务；从预训练进入后训练则新建任务和新的 optimizer/scheduler，不继承预训练动量。恢复任务要求模型、词表、数据哈希和规范兼容；遇到改变应创建新分支而不是假装精确续训。

先写临时文件再原子替换并校验元数据/校验和。外部不可信 pickle 检查点不可无提示反序列化；首版只恢复本系统生成且验证过的状态，导出推理权重使用安全格式。训练状态安全加载方案写入 README。

## 6. 真实训练任务与实时观察

任务状态：queued → running → pausing → paused → running；结束为 completed / cancelled / failed / interrupted。记录错误、退出码和最后完整检查点。后端重启后恢复任务列表，但无存活 worker 的旧 running 任务标为 interrupted，不能永久显示“训练中”。

单 GPU 同时只允许运行一个正式训练 worker。使用系统级互斥/持久化协调避免多个 API 进程抢占；开发 reload 也不能重复拉起同一任务。对状态修改提供幂等检查与明确 409 冲突响应。

训练事件包括事件序号、时间戳、run_id、stage、global_step、指标、设备、检查点与错误。通过 SSE 增量输出，并支持重连后补事件；刷新浏览器不丢失任务。SSE 不是训练状态唯一存储。

梯度范数按 unscale 后、clip 前统计。显存区分 PyTorch allocated/reserved 与设备总使用量；GPU 利用率拿不到时显示不可用，不拿显存代替利用率。权重分布用低频抽样并标明采样步骤；动态图表以真实事件为输入。

默认测试最近一个已落盘的不可变检查点，可在 CPU 推理，显示其来源。不要从另一个线程直接读写正在更新的训练模型；不要为了每次测试复制整套 100M 权重占满显存。GPU 训练与 GPU 测试竞争时排队或明确切换测试设备。

捕获 OOM/NaN/Inf，保存最后可用完整检查点，释放进程资源，并返回诊断。降低微批次/长度或启用重计算必须留下配置变更记录；不静默反复重启。

## 7. 最小 API 契约

可调整命名，但覆盖以下功能，并由 OpenAPI schema 与前端类型保持一致：

| 方法/路径 | 功能 |
|---|---|
| GET `/api/health` | 服务状态 |
| GET `/api/system` | 硬件/运行时/精度能力/运行设备 |
| POST、GET `/api/datasets` | 文本/标注数据集保存、导入、列表 |
| POST `/api/datasets/validate` | 标注校验、冲突与覆盖错误 |
| POST、GET `/api/models` | 新建配置/随机模型、列表、真实参数量 |
| POST、GET `/api/runs` | 新建预训练/后训练任务、列表 |
| GET `/api/runs/{id}` | 持久化状态、配置、指标摘要 |
| POST `/api/runs/{id}/pause`、`resume`、`stop` | 状态控制 |
| GET `/api/runs/{id}/events` | SSE、事件 ID 与重连补发 |
| GET `/api/runs/{id}/checkpoints` | 检查点元数据 |
| GET `/api/checkpoints/{id}/export` | 显式导出 |
| POST `/api/inference/mlm` | text + mask_positions + checkpoint_id |
| POST `/api/inference/units` | text + checkpoint_id + threshold |

提取响应的参考字段：

```json
{
  "text": "我养了十二只猫，它们都很乖很可爱",
  "units": ["我","养","了","十二","只","猫","，","它","们","都","很","乖","很","可爱"],
  "spans": [[0,1],[1,2],[2,3],[3,5],[5,6],[6,7],[7,8],[8,9],[9,10],[10,11],[11,12],[12,13],[13,14],[14,16]],
  "offset_unit": "unicode_codepoint",
  "rule_version": "unit-v1"
}
```

上例是契约示例，不是某个已训练模型的推理记录。真实响应还应带 checkpoint_id、threshold、device、latency_ms、原始边界概率及 warning。没有推理就不能填充虚构概率或耗时。

统一返回有 error code 的验证错误。边界训练不能偷偷丢弃超长样本：首版可拒绝并展示确切长度和拆分建议；有标注训练可按已知单元边界分块并说明上下文损失。推理超过位置容量时默认明确报错，日后再做有测试的重叠窗口，不做静默截断。

## 8. 安全和本地性

默认只监听 loopback；开发 CORS 精确放行前端来源，不通配放行。状态修改与 SSE 用一致的本地会话/来源校验，不能让任意网页在后台启动本机训练。任意路径读取/导出、命令拼接、路径穿越均需阻止；文件存放在受控 workspace。

导入限制大小、类型与结构，不直接执行上传内容。命令调用采用参数数组，不拼 shell。训练语料、检查点、测试文本默认不离开本机；不引入账号/云端数据库/遥测作为必要依赖。

## 9. 建议实现顺序

先实现可测的数据契约、字符词表、编码器、MLM 与边界损失；再做有限步数训练、检查点、暂停恢复和推理 API；接入实时任务与 GPU 检测；最后完成两页三栏真实联动与页面测试。不是只完成计划后停下。

以 `ACCEPTANCE.md` 验收。交付 README、源码、依赖锁定、CPU 测试命令、本机 GPU 冒烟命令、两页截图、实际测试输出、限制与未完成项。无 GPU 可完成代码与 CPU 测试，但 GPU 测试必须明确标为未执行。

正式训练规模、可靠泛化成绩、具体耗时和峰值显存，均以用户机器和独立测试集实测为准，不在实现阶段承诺。
